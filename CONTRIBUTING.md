# Contributing to WarEra Lab

Thank you for helping improve WarEra Lab.

## Before you start

For bug fixes and small documentation improvements, a focused pull request is welcome. For substantial features, simulation mechanics, API integrations, architectural changes, or new data collection, please open or join an issue first so the assumptions and scope are visible before implementation.

## Ground rules

- Keep changes focused and reviewable.
- Do not commit API keys, credentials, tokens, private user data, production secrets, or copied proprietary assets.
- Prefer official WarEra API documentation and directly observed API behavior over undocumented assumptions.
- Clearly identify community-sourced or inferred game mechanics.
- Preserve the distinction between observed, derived, assumed, and user-overridden values.
- Add tests for calculation logic and API normalization when implementation begins.
- Avoid coupling simulation logic directly to UI components or raw API response shapes without a documented reason.

## Pull requests

A pull request should explain:

1. what changes;
2. why the change is needed;
3. how it was validated;
4. whether it changes any API/data assumptions;
5. whether it affects privacy, credentials, caching, or security.

Use the repository pull-request template where available.

## WarEra and third-party material

Do not add WarEra artwork, logos, proprietary text, or other third-party material unless its use is clearly permitted and documented. Links, factual references, and API integration should be used conservatively and with appropriate attribution.

WarEra Lab is independent and is not affiliated with, endorsed by, or operated by WarEra.
